## 实施顺序

1. FDN-01：统一版本源、release-check 基础和可复现测试摘要。
2. SEC-01 expand：租户 transaction helper、受控身份/Worker 函数、policy 迁移与真实 PostgreSQL fixture。
3. SEC-01 enforce：逐表 RLS、受限角色、pool reuse 和双 Worker 验证。
4. 并行交付邀请/onboarding 与 review attempt 两条垂直切片，每条同步 E2E。
5. 收口 AIQ、metrics/alerts、backup/restore、coverage/scan 和 release manifest。

## 当前 fail-closed 边界

- `jobs` 的 RLS/`FORCE RLS` 仍未启用；0018 仅是 expand，不能据此宣称租户数据库隔离完成。
- tag CI 已调用 manifest verifier，但在最终机器证据聚合与 artifact 下载链路完成前会主动阻断所有 release tag。
- 当前 manifest verifier只实现 `rc.1` 绝对阈值；后续 RC 的上一已接受 RC 比较与正式版 14 日 promotion evidence 未实现，因此保持阻断。
- 邀请仍使用 v0.4 明文 `invite_codes.code` 生产路径；新增 token primitive 尚未接入，数据库/API 完成前不得签发 v0.5 邀请。
- review attempt 仍无持久化事务；旧 complete endpoint 也尚未退场，当前只交付领域契约与调度 policy。
