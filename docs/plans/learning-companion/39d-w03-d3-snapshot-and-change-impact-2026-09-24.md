## 0. 一句话结论

**快照的锚点已经在了**——`evidence_snapshots_v2` 里就有 `block_id` + `start_offset`/`end_offset` + `quote_hash` + `block_content_hash` + `source_content_hash`，不必新造一套。**缺的是两件事**：①**判定顺序**（谁受影响、按什么先后）②**一条现在没人做的事**——内容变了之后**没有任何代码去标受影响**（实测：全仓没有变更影响逻辑）。

## 2. 决定一：内容快照的形状

**合同（39 §15.3-2 原话的落地）**："学习输入冻结实际正文、可用引用摘录和内容哈希，**不能只保存可能继续自动保存的 `noteVersionId`**。"

一份**学习输入快照**由三件组成，三件缺一不可：

| 组成 | 已有来源 | 为什么不能省 |
| --- | --- | --- |
| **实际正文** | `note_versions.content_hash`（哈希）+ `note_blocks` 按 `version_id` 取正文 | 版本 ID 会指向"当前那一版"，而"当前"会变；哈希是判"变没变"的唯一依据 |
| **引用摘录** | `evidence_snapshots_v2` 的 `block_id` + `start_offset`/`end_offset` + `quote_hash` | 主张的**依据**是具体那一段，不是整篇；整篇没变而这一段被改也必须能发现 |
| **内容哈希** | `note_versions.content_hash` + `block_content_hash` + `source_content_hash` | 三层不同粒度：整篇、块、来源。少一层就会在某一类变化上失明 |

### 2.1 "没有副本"是一个独立的状态（不是空字符串）

`evidence_quote_copies_v2` **存量不回填**（0275 的决定）。所以读侧**必须**能区分三种情况：

| 情况 | 含义 | 能做逐字比对吗 |
| --- | --- | --- |
| 有副本 | 密封时冻结了原文 | **能** |
| 没有副本（存量） | 原文已无从确定 | **不能** —— 只能降级到"无法确认"（§3 第 4 层） |
| 副本存在但内容为空 | 不可能（列 `NOT NULL` + `quote_hash` 长度 CHECK=64） | — |

**这条必须写进实现**：把"没有副本"当成"比对失败"是对的，当成"内容没变"是**把伪造写成证据**。

### 2.2 一致读取（39 §3.4）

- 已保存的笔记直接开始；**有未提交编辑或保存失败时**，明确提供「先保存再开始」与「按上次已保存内容开始」两者之一，**不能默默忽略眼前修改**（39 §3.4）。
- **开始学习、主动复习、制作卡片采用相同原则**（39 §3.4 末句）——三处共用同一个一致读取入口，不各写一遍。
- 保存或一致读取失败时**不创建看似已开始的空轮次**；草稿保留并可重试（D1 §5.1 的同一行）。
- 正文太长时先给**可核对的结构与局部准备状态**，**不能静默截取前半篇并称为整篇输入**（39 §3.4 末句）。

## 3. 决定二：判定顺序（D3 的核心交付）

**从确定到不确定，四层。一旦某层判定"受影响"就停止，不许用低确定度的层去推翻高确定度的结论。**

| 顺序 | 判据 | 确定度 | 结论 | 数据来源 |
| --- | --- | --- | --- | --- |
| **1** | **显式修改关系**：用户或系统显式记录的目标修订、删除、拆分、合并 | 最高 | 按显式关系处理（新目标不整体复制旧成绩） | 目标修订记录 / 显式变更事件 |
| **2** | **稳定锚点仍指向同一段**：同一 `block_id`，`start_offset`/`end_offset` 覆盖的文本 `block_content_hash` 未变 | 高 | **未受影响**，保留历史适用性（旧结论仍可用于推荐与学习判断） | `evidence_snapshots_v2` + `note_blocks` |
| **3** | **引用哈希比对**：`quote_hash` / `source_content_hash` 与当前版本比对 | 中 | 变了 → 受影响；未变 → 未受影响。**只有存在 `evidence_quote_copies_v2` 副本时才能做逐字比对** | §2.1 |
| **4** | **不确定** | 最低 | **不继承**：展示当时与当前依据供核对，**不按标题或位置自动迁移**（39 §10.2 末行） | — |

### 3.1 红线：模型相似度只能建议

39 §15.3-5 原话：**"模型相似度只能提供建议，不能独立授权能力继承。"**

落地成三条可检查的约束：

1. **模型相似度的输出只能落在第 4 层**，作为"待确认建议"呈现；它**不能**把结论提升到第 2 或第 3 层。
2. **不许按标题相似自动继承**（39 §4.2、§16.17）：`title` 或显示名相同**不构成**同一目标的证据。
3. **默认去重范围**＝同工作区、同笔记、**同一可确认的目标及能力维度**（39 §4.2 末段）。跨笔记仅有相似关系时**分别记录**，暂不自动抵扣复习。

### 3.2 为什么顺序不能反

把第 3 层放到第 2 层前面，就会出现"锚点没变但哈希比对失败 → 误判受影响"（例如文本被重新排版导致 `source_content_hash` 变、但那一句没变）；反过来把第 4 层提前，就会"因为不确定所以全判受影响"，把 39 §10.2 第一行"标题、排版等非实质变化 | 保留目标关联与个人状态，不新增学习任务"直接违反。**顺序本身就是判据。**

## 4. 决定三：检测到之后做什么（39 §10.2 的表，逐行给动作）

| 变化 | 体验与证据处理 | 实现要点 |
| --- | --- | --- |
| 标题、排版等非实质变化 | 保留目标关联与个人状态，**不新增学习任务** | 第 2 层命中即返回"未受影响"，不产生任何新任务 |
| 新增例子或补充说明 | 保留未变主张的历史；新增部分按实际需要推荐，**不自动判整篇待重学** | 只有**被引用段**变了才影响该目标；新增段不牵连旧目标 |
| 新增目标 | 从**未观察**开始，**不继承相邻内容的表现** | 新目标与相邻内容的历史无关 |
| 主张、答案或适用条件改变 | 标出受影响目标与卡，**先核对或重学**；旧结论仅对旧内容成立 | 第 3 层命中 → 标受影响 + 生成"待核对"；**不删除**旧结论 |
| 删除、拆分、合并目标 | 保存**旧身份**与明确的变化关系；新目标**不整体复制**旧成绩 | 走第 1 层；`supersedes` 链要能表达"从哪个目标变来的" |
| 无法确认变化意义 | 展示当时与当前依据供核对，**不按标题或位置自动迁移** | 第 4 层；界面给两侧对照 |

### 4.1 三条"不做"

- **不自动改正文**（39 §10.1："不替用户自动覆盖原文或改正争议内容"）。
- **不自动清空进展**（39 §10.1 末段："不能把自己的学习备注一写进去就清空已有进展"）。
- **不把受影响说成人退步**（39 §11.4 的第三轴："内容适用性 | 依据适用、内容更新、待核对、无权限 | **资料变化就是用户退步**"——这是"不能混成的含义"那一列）。

### 4.2 待核对与能力结论的关系

- 受影响的目标**不得到**新结论；旧结论**只对旧内容成立**（39 §10.2 第 4 行）。
- 待核对的主张**不能成为标准答案、正式能力判定或可开启复习的卡片依据**（39 §4.1、§16.26；D2 §4.3 的 `permission_revoked` / `stale` 是两件不同的事）。
- 用户**修改原句或补来源**后，只**重新检查受影响目标**（39 §4.1 末段）；其他记录保持原状。

## 5. 决定四：计划修订与轮次恢复的历史不变

39 §4.3、§5.5、§16.14、§16.17：

| 要求 | 落地 |
| --- | --- |
| 计划调整**保留理由与版本**，历史记录**实际走过的内容**，不能覆盖最初计划并伪装从未变更 | 计划是**追加式修订**（每次调整记一条：理由、时间、变更前后），不是覆盖写 |
| 快照冻结"当时用了哪一版目标"，**不意味着每个快照都重新产生一套身份** | 快照引用目标身份；身份跨轮复用（39 §16.17："可确认同一目标时复用身份和适用历史，不新建一套卡或日程"） |
| 每道用于能力判断的题在**呈现前**固定目标、题面、评分条件与初始证据资格；后续求助可**收紧**资格，**不能看到答案后改题意或放宽条件**（39 §4.3 末段） | 冻结发生在呈现前（D5 §2 的 `prepare`）；收紧是**单调**的 |
| 未完旅程遇到修改 → 提供「继续当时内容」或「按当前内容新开一轮」 | 映射到 D1 的 `closed(superseded)` + 新轮 |
| 历史回放读**当时**的产物，不重新生成 | D4 §5.4 已钉 |
| **终止原因**：`target_fingerprint_changed` 是运行期指纹变化（既有合同），与**跨版本**的变更影响是两件事 | 两者都保留，但**不共用同一个 reason code** |

## 6. 谁执行判定、什么时候跑

### 6.1 一个新服务：变更影响

```
detectChangeImpact(input: {
  workspaceId, userId, noteId,
  fromVersionId, toVersionId,
}) → Array<{
  objectiveId, 
  layer: 1 | 2 | 3 | 4,          // §3 的判定层
  affected: boolean,
  evidence: { blockId?, offsets?, quoteHashMatches?, copiesAvailable: boolean },
  reasonCode: string,
}>
```

**必须返回 `layer` 与 `evidence`**：没有这两样，界面就说不清"为什么判它受影响"，而 39 §13.3 要求状态文案是"这一处条件更新了，先核对这里"，**不是**"整篇退步"。

### 6.2 触发时机

- 在**笔记保存产生新版本之后**触发（有稳定的 `fromVersionId`/`toVersionId`）。
- **不在每次自动保存时全量扫**：按 39 §10.2 的取向，非实质变化要能"不反复打断用户"。
- **判定结果不缓存成事实源**：它是投影（39 §15.2 末句），重算即可，不新增一张"变更影响表"。

### 6.3 与调度、卡片的关系

- 受影响 → 相关**安排**先核对（不执行），不是取消（39 §9.3 末行："内容改变或权限不足 | 相关旧结论不套到新内容 | 受影响项**暂停执行或先核对**"）。
- 卡片：**修改笔记只检查受影响卡**（39 §8.5）；修订卡面但**目标与依据未变可延续目标记录**（39 §8.5）。
- 归档：笔记归档时其旅程新入口、所属卡片与相关回访**均暂停**，历史按权限保留；**恢复归档不把错过的每个日期补成作业**（39 §8.5 末段）。

## 7. 验收判据（实施时逐条可跑）

| # | 判据 | 怎么算过 |
| --- | --- | --- |
| 1 | 非实质变化不打扰 | 只改标题/排版 → 判定 **layer=2 / affected=false**，且**不产生任何新任务** |
| 2 | 引用段变了才影响 | 改**未被引用**的段落 → 该目标 `affected=false`；改**被引用**的那一段 → `affected=true` |
| 3 | 无副本不冒充一致 | 取一条**没有** `evidence_quote_copies_v2` 副本的旧快照 → 判定必须落 **layer=4**，**不得**返回"未受影响" |
| 4 | 相似度不提升层级 | 构造"标题相同但内容不同"的两篇 → 断言结论**只在 layer=4**，且不产生继承 |
| 5 | 不受影响的历史仍可用 | layer=2 命中 → 旧结论仍可用于推荐与学习判断，且**保留原日期、原快照**（39 §10.2 末段） |
| 6 | 计划修订追加不改写 | 调整一次计划 → 断言最初的计划仍可读、理由与版本成对存在 |
| 7 | 题面不被事后放宽 | 提交后求助 → 断言证据资格**收紧或不变**，不出现放宽 |
| 8 | 归档恢复不补债 | 归档→恢复 → 断言不生成"错过的每一条"待办 |

## 8. 未决项与落点

| 未决项 | 为什么本文件不定 | 落点 |
