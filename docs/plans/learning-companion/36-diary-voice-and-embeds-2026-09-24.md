# 桌宠日记：语气与嵌入物的返工（2026-09-24，两轮）

范围：**日记这一篇字**——素材采集、prompt、服务端机器闸、图注与引用的成稿形状。
`companion_daily_summaries` 的表结构、调度、失败分诊、记忆派生（digest）都不动。
代码集中在 `workers/ai-worker/src/handlers/companion-daily-summary.ts`（+ 同名单测）
与 `packages/shared/src/companion-persona.ts`（第二轮新加的两句音色）。
草案出处：[22-real-desktop-pet-memory-context-prd-tdd.md](./22-real-desktop-pet-memory-context-prd-tdd.md) §15.4/§15.5（v1.8 那一版）。

## 0. 一句话结论

**第一轮**（§2–§9）：用户判词"不自然、AI 味儿太重、引用和图片插入很生硬"。逐篇读过
库里的十篇日记之后，**这不是一个语气问题，是四个**：引用候选按"最长段落"取，取到的
常常是推广导语、招聘启事和测试探针串；图片被 prompt 逼着"说到它"，于是她写
"我倒是挺配合地把图摆了出来"；反重复只有 prompt、没有闸（同一句开头连写两天）；
报数闸只认阿拉伯数字，素材行里那句写给模型的说明被她整句抄走。四处都改成了
"素材给干净的 + prompt 说清楚 + 服务端真的核"。

**第二轮**（§10–§13，同日）：用户判词"文风还是怪怪的"。第一轮加的全是禁令——
**禁令压得住症状，压不出音色**。真因是日记链路自成一个文学腔，与聊天链路分裂，
而用户对她的聊天声音是满意的。第二轮按用户六条裁定重做音色与素材结构，
并且量到一个必须记住的结论：**同一套 prompt 连跑四稿，两好两坏——方差本身就是天花板**。

**要接着改日记，从 §13 的残留清单起。**

## 2. A 组：引用块选的是垃圾

| 实录 | 出处 |
| --- | --- |
| 09-23 引了 251 字的推广导语「不赶进度、专注打磨！今天想和大家聊聊我们最新发布的 IndexTTS 2.5…」，还被硬切在「…宁愿推」 | Personal Beta 09-23 |
| 09-21/09-22 引了用户留在笔记里的探针串「这段全空间都读得到｜A 加的那句｜实窗量测 22:48:46｜…」（333 字），她还替它编了解读 | 验收空间 09-21、09-22 |
| 09-21 同一天两条引用出自同一篇笔记，label 一字不差重复两遍，内容都是术语定义 | 验收空间 09-21 |
| 正文里留着编号字面：「心里莫名安定下来。 引1 还有那条自动化数据管线…」 | 09-18 |

根因（`:504-530` 那一版）：`ORDER BY length(content) DESC` + `left(content, 200)`。
"取最长"正是推广导语与岗位要求最长的那种笔记，而 200 字硬切会把句子截断；
编号泄漏则是因为规则写了"别把编号写进句子"，服务端**没有核**。

改法（`:218` / `:237` / `:245`）：

- SQL 侧：同一段原文去重（`DISTINCT ON (trim(content))`）、长度只收 20–180 字
  （超了一整条不要，不再硬切）；
- TS 侧 `isQuotableQuote`：链接/「网页链接」/`记得 Star`/表情符号/表格分隔符碎片全部挑掉；
- `pickQuoteCandidates`：**每篇笔记最多一条**、最多三条；序号条目（`1. …`、`- …`）
  排到真句子后面——09-23 那篇的候选池里最长的两条是岗位要求；
- 正文里的 `图N` / `引N` 由 `stripEmbedRefs`（`:754`）机械剥掉并 warn，
  不判失败：编号只用来定位块，为它烧一次重采样、甚至让这一天没有日记都不值。

## 3. B 组：图片是"摆出来的"

- 09-23 原句：「后来你问我插图的事，我倒是挺配合地把图摆了出来」——事是真的（用户当天
  确实让她把插图摆到对话里，`companion_messages` 12:35–13:50 有原话），但写进日记就是
  自曝机制。prompt 规则 9 那句"图放在你说到它的那段后面"逼她必须"说到它"。
- 图注是机器拼的「《X》· 第 1 张」——图录味；两张图的图注还会是同一个编号格式。

改法：

- **图注由她自己写**（image 块新增可选 `caption`，服务端拼上《笔记标题》出处，
  `diaryImageLabel` `:833`）。写不出来退一句人话（`《X》里的一张图`），
  报数或带编号字面的图注也退人话；
- 她看不见图里画的是什么（读图要外发字节），所以素材里补上**这张图挨着的那段正文**
  （`LEFT JOIN LATERAL`，`:561`）——这是她能对着一张看不见的图说出人话的唯一依据；
- 规则改成：只在你正好写到那篇笔记时放；不许写「给你看图」「把图摆出来」「插图」
  这类动作；放了就要配一句（二十字以内）；**不要描述图里画的是什么**；
- **每篇笔记最多一张图**（`pickImagesPerNote` `:110`）。第一轮真跑就是两张同笔记的图
  被塞进两段、第二段跟那篇笔记毫无关系、两条图注还是同一个干饭梗——候选给六张，
  她就当配额在用；
- "第 N 张"对齐对话链路（`created_at DESC, id`）：两个面各报一套序号，
  用户按日记里的"第 3 张"去问她要，出来的是另一张。

## 4. C 组：反重复只有 prompt，没有闸

- 开头：验收空间 09-21 与 09-22 两篇的前 19 个字逐字相同
  （「夜深了，屋里静得只剩下时钟走动的声音。我坐在桌…」）。查过 `jobs`：
  09-21 是前一天 17:00:50 跑完的，素材里确实把它的开头喂给了 09-22——
  **规则 12 被无视了**，因为没有闸。现在 `repeatedOpeningIn`（`:800`）前 10 字相同就退回重写
  （只在第一轮退，第二轮收下——同样的开头也不该让这一天没有日记）。
- 人格例子：`hungry-fish` 那四条例子在 09-20～09-23 的日记里被逐字搬了四遍
  （「干饭不积极，思想有问题嘛」「我这岗位主打一个吃白饭」「摸鱼不是偷懒…」
  「我在后台偷偷猜了个词」）。现在 `exampleEchoIn`（`:776`）按十连字窗口判"抄"，
  只在第一轮退；口头禅「我去吃饭了」五个字撞不上，照旧允许。
  送进 prompt 的例子也从 5 条收到 3 条。

## 5. D 组：报数闸漏中文数字，素材里的说明被抄

- 09-20 原句「今天学了半小时上下」——素材行写的是
  「今天你学了半小时上下（这只是感觉，别在日记里报数）」。**写给模型的说明写在素材里，
  等于请她抄**；而规则 2 只禁阿拉伯数字，她换中文数字，闸门照放。
- 改法：素材行去掉了那句括注（改成事实口吻）；`countingToneIn`（`:738`）补一条中文数字闸。
  量词表**故意比阿拉伯那道窄**：不收「天、周、个、一、几、遍」——
  「这两天」「一个念头」「几天没见」「那句话他念了两遍」都是正常的话，
  误判一次的代价是一天没有日记（两次不合规矩就判失败）。

## 6. E 组：没有档案的日子落回通用文学腔

- 无档案空间（伴星取系统默认人格，persona 字段全空）的三篇：
  「像一颗划过夜空的流星」「时间悄无声息地溜走」
  「这种生疏感让我保持着一份客气的距离」（把 familiarity 设定念了出来）。
- 真跑第一轮（安静日：整天只有页面轨迹、零对话）**仍然**是两段纯抒情：
  「仿佛只是隔着玻璃在看别人的笔记」。
- 改法分两层：
  1. 规则组：不写比喻、不写等待和思念、不在结尾升华、不把设定念出来
     （规则 5 里那句"在等什么"也删了——那是等待腔的邀请）；禁词表补「后台、系统、
     记录、事件、状态、任务、流程」；
  2. **安静日单独一档**（`quietDay` `:159`/`:695`）：没有对话、没有笔记、没有学习、
     没有提醒、没有念头、没有记忆的日子，篇幅档位不跟活跃度走（一到两段），
     并要求"至少写两件能指着说的东西"+"「仿佛」「宛如」「疏离」「徘徊」「无意识地」
     这类词都不要"。实测这一档连栽三跑，抽象禁令无效，最后是这两条能核对的要求加上
     一份从她自己产出里抄下来的词表才拽回来（第五跑）。

## 7. 顺手修掉的两处

- **失败的重跑会抹掉已经写成的日记**。第三轮真跑那天第一次不合规矩，失败行把
  revision 1 的正文清成了空块，屏幕上从"有日记"变成"她没能写下来"。
  `persistDiary` 的 upsert 现在带 `WHERE status <> 'generated' OR EXCLUDED.status = 'generated'`
  （`:1300`）：已经写成的日子只被**成功**的重跑替换，失败照旧记进 job 的 `last_error`。
- **失败日志说不出撞了哪道闸**。原来只有一句"两次都不合规矩（报数 / 太短 / 输出不是 JSON）"。
  现在每轮被退回来的判词先落一条 info（`companion diary draft rejected`），
  最终异常也带上最后一次的判词。

## 9. 还没动 / 待定

- **引用块要不要保留**：按用户裁定"严选后保留"，没有推翻这个能力；
  如果继续觉得多余，去掉的入口就在 `collectMaterial` 的 `quoteRows` 一段。
- **图注里的出处**：现在是「《笔记标题》· 她的一句话」。标题超过 32 字会被截
  （"…哔哩哔哩222"这类重复导入的标题会截到"…222"），没有更聪明的去处。
- **`hungry-fish` 预设文案里的「刚在后台偷偷猜了个词」**：一句系统词，落在用户可见的
  人格例子里（`packages/shared/src/pet-persona-presets.ts:103`）。改预设只影响新套用的人，
  存量档案是拷贝——没动，留给产品裁决。
- **安静日的上限仍是"最多 N 段"**：没有为它单独收窄服务端段数上限，
  靠的是 prompt 里那两条能核对的要求。要更硬就在 `diaryLengthOverflow` 里按 `quietDay` 收。
- 生成仍然可能整篇失败（两次不合规矩 → `diary_output_invalid`）：这是 0250 定的形状，
  本轮只让它可复盘、不误伤已写成的日子。

# 第二轮（同日）：换成她自己的声音

## 10. 用户裁定的六条（审美决定，不再讨论）

第一轮交付后用户的判词是"感觉咋说呢，文风还是怪怪的"。用苏格拉底式提问一条条问下来，
六条定死了（每条都给了同一天的样例文本让用户挑句子，不是问抽象偏好）：

| # | 问题 | 裁定 |
| --- | --- | --- |
| 1 | 这篇日记的主角是谁的一天 | **她自己的日子**（用户的行为退成背景） |
| 2 | 她该用哪种声音 | **跟聊天里同一个声音** |
| 3 | 能不能写人的日常（手指、键盘、食堂） | **都可以，是她的想象**（不要俗套） |
| 4 | 一篇的完成度 | **一件小事写透**（宁少勿全） |
| 5 | 要不要写她自己没做好的部分 | **要，那才是她的一天** |
| 6 | 图注要不要为"写得出内容"而开读图 | **允许读图** |

第 3 条推翻了我自己上一轮的判断：我原本想把身体感受禁掉（那是"借人类感官填空"的解药），
但那会打死"爱吃白饭的大肥鱼"这类人格——贪吃和饿就是人设本身。留的退路是：
俗套回潮再收紧，不预先禁。

## 11. 改了什么

### 11.1 音色同源——但**不是整段注入**

`packages/shared/src/companion-persona.ts` 新增 `COMPANION_VOICE_STYLE_LINES_V1`：
从对话那份角色底座里**逐字取出**的两句（默认语言 + 口语与回应词/别重复开场白/每次都是新内容）。
`companion-persona.test.ts` 钉住它必须是底座里的原话，并钉住"把球抛回去""不假称自己有身体"
**不在**这两句里。日记 prompt 的 `# 你说话的样子` 引用它。

> **为什么不是整段**（这是第二轮最贵的一课）：第一版按方案逐字插了整段
> `COMPANION_CHARACTER_BASE_V5`，真跑立刻漏三处——
> 借"把球抛回去"写出「像把球抛出去却没人接住」；照"不假称自己有身体"写出
> 「哪怕你知道我只是一段代码，没有真正的肢体」；把"黏人但懂分寸"念成
> 「不必像初次见面那样拘谨，可也不能完全没分寸……不需要刻意讨好，也不需要过分冷淡」。
> 而五段对话示范**每一段都以问句收尾**，正好教出日记最扎眼的那个毛病。
> 一份写给对话的规矩，整段搬进日记，就会变成她的意象库和自我声明素材。

### 11.2 素材从"当天发生了啥"改成"她的一天"

`lines: string[]` → `pieces: {text, group: her|his|backdrop, weight, at}[]`
（`renderMaterial`）：线头单列一行，然后 `# 她的一天` / `# 他的动静（背景）` / `# 时间骨架`。
超预算**从末尾丢**——先丢骨架，她的那一天最后才动（旧实现按时间平铺、从前面丢，
等于把她的上午换成他的晚上）。权重：她的原话 3 > 她的念头/提醒/记忆 2 > 他的动作 1 > 骨架 0。

- `pickDiarySubject`：确定性挑"这一天的线头"（权重优先，同分取当天最早），
  规矩 2 要求只写它；嵌入物也跟着线头那篇笔记排前面。
- **时间折段**：`dayPartOf`（上午/下午/傍晚/晚上/深夜）替换素材行里精确到分的 `HH:MM`，
  节奏行用 `clockPhrase`（"晚上八点多"）。09-24 实录「下午两点多开始改那个无标题笔记，
  后来又在傍晚新建了一篇同名的」就是把日志翻译成散文的味道。
- **人称统一**：节奏行以前写"他第一次来找我是…"，而规则 1 要求她称对方为你——
  素材自己都不统一，她第一段"你"第二段"他"（四稿里两稿漂）。素材改成"你今天第一次来找我是…"。
- 安静日（`quietDay`）：删掉第一轮加的"至少两件能指着说的东西"（与"写透一件"直接冲突），
  规矩 2 换成"没剩下线头就写一小段，或者写一句今天没什么事"。

### 11.3 规矩从 13 条改到 12 条，并删掉两条泛化禁令

- **删**「不写比喻、不写等待和思念」：与音色基线自己的口语冲突，压症状不产音色。
  只留窄版「心情不靠比喻和天气写」+「不要在结尾把这一天总结成什么道理」。
  等待与思念改由结构消灭：她是主角、只写一件事，就没有等他的戏份。
- **删**禁词表里的「页面、界面」：素材里就写着"资料页/复习页"，安静日还要求她写
  "你在哪一页上"——现行 prompt 自相矛盾。**加**「代码、程序」（她真写出过"我只是一段代码"）。
- **删** `familiarity` 那句（"刚认识该客气一点"）：它正是"把设定念出来"的邀请。
  活跃度也不再进 `renderPersonaBehaviour`（那句"回复偏短"是对话的行为，日记由篇幅档管）。
- 篇幅档 2/3/4 段 → **2/3/3**：4 段会被当配额铺成四件事。

### 11.4 读图（能力已建，**dev 没验到开着的那条路**）

`pickImageToRead`：政策关着 / 没有线头 / 线头不在这篇 / 图 >2MB → 一律不读。
读一张（不是六张）：每张 20–40s，日记 handler 预算 90s、租约 120s。
`describeDiaryImage` 三条降级路径全部 `return material` 原样退回，**绝不进
`classifyDiaryFailure`**——政策关着时发出去会抛 `AIDataPolicyDeniedError`，
被归成 `consent_required` 就等于把这一天判死。审计报 `dataCategories: ["image_content"]`
（治理层 `governance.ts:573` 会据此再查一次开关，这是"取字节那几秒里用户拧了开关"的门）。
描述进素材行时明说"这是别人转述给你的，别写成你亲眼看了它"。

> **未验证**：dev 这个账号 `sendImageContent=false`，所以真跑只验到"政策关着不读、
> 整天不失败"这条降级路径（跑通了）。**"图注写得出图里是什么"这条主路径没有真跑证据**，
> 只有单测与 prompt 文本。要验必须先把那个开关打开（会把笔记图片字节发给 bigmodel）。

### 11.5 图不再靠猜：`imageShape`

宽高是库里现成的、我们**真的知道**的事实，而她四轮里猜了三次图里是什么
（「那张竖屏的界面截图」「人挤人」）。素材行现在给「（竖长条一张，这个我们是照实量的）」。

### 11.6 新增三道闸（都只在第一轮退，第二轮收下）

| 闸 | 实录 |
| --- | --- |
| `selfPutdownIn` 道歉与自贬 | 「这种懒病没救了」「我不是在敷衍」——用户要她写笨拙，但记事不是检讨 |
| `endsInQuestion` 问句收尾 | 「不知道你现在是不是已经睡着了？」「是该回得热络些，还是保持分寸？」 |
| `thirdPersonForUserIn` 写成"他" | 「中午那会儿他随口一句」「这就是他下午随手敲进去的东西」 |
| `captionEchoIn` 图注照抄描述 | 读图之后她手里有两句现成的话，照抄最省事 |

### 11.7 引用候选补两道（第二轮又栽了两次）

- **必须成句**：没有句末标点的一律不进（拦掉「aside啊说的哈回电话给啊合适的哈…」，
  她还顺着编了段"大概是键盘被猫踩了一脚"的解读）；
- **光有句号不算**：必须有 ≥8 个汉字连成一串（拦掉「修改笔记。12312 123123123123」，
  句号是真的、句子是假的；被留下来的那句技术引用最长连串有十个字，不误伤）。

## 13. 第二轮的残留

- **读图主路径没验到**（见 11.4 的框）。
- **方差**：想再压，能做的三件事按代价排——① 把"只写一件事"变成结构（一次只喂她线头
  那一条素材，其余不给）；② 段数上限按 `quietDay`/素材条数收；③ 换温度或换模型重测。
  ①最有效但会牺牲"她自己挑事写"的空间，没做，等用户裁决。
- **她仍会写"我把图摆出来给你看"**：那一天用户确实让她摆过（素材里有原话），
  所以这句是真事。规则 10 禁的是"描述自己在放图"这个动作，边界靠她判断。
- **比喻没有硬闸**：「像乱麻一样缠过来」这类句子会漏。判据不可靠，误伤一次等于一天没日记。

## 14. 本轮收紧成稿输入（09-24，针对仍然跑偏的库内新稿）

再读库里十篇，最新的 Personal Beta 09-23（revision 11）仍从「大肥鱼是谁呀」写到
IndexTTS、复习卡与「我把图片一张张摆出来给你看」。这是此前 §13 提到的方差：
`pickDiarySubject` 只把一条素材标成线头，**当天其余消息、笔记、图和引文仍全部在 prompt 里**；
输出样例也同时摆着 text、image、quote 三种块，看起来像要求每种都放。

这轮直接在生成前加 `focusDiaryMaterial`：只留线头、它前面最近的一条用户原话（十五分钟内），
图片和引文只留线头所属笔记的候选；没有笔记关联就不给嵌入物。对话提到当天碰过的笔记时，
把该笔记 id 接到她那句回复上。相同分钟的对话按真正的 `created_at` 排序，避免把她说完后的
下一句用户输入错配成起因；prompt 把这一幕按「你先说 / 我回答」的顺序摆出来。
改笔记的时段用实际修改时刻，不再用最初创建时刻。

输出样例改成只有正文块，image/quote 作为可选写法单独说明；图注先说她的一句话，出处退到句尾。
prompt 把想象限定为「她的念头」，不再把未发生的动作写成事实；两段上限替代原来的三段，
活跃档只改变每段句数。优先挑她明确承认没弄懂、没答好的片段，避免普通问候总抢到开头。
模型温度从 0.85 收到 0.6。派生记忆的 digest 改由线头事实确定性生成：一次不覆盖日记的试稿
把「我是元气小猫」错归给用户，连 digest 都写成「元气小猫想学习」；这样的错不能再回流成记忆。

验证：日记单测 48/48、worker 全量 815/815、类型检查通过。三次**不覆盖已有日记的模型试稿**：
第一稿仍三段跨话题并编动作；收篇幅后第二稿仍把两人说话记反；补上发生顺序后，
第三稿换到「她承认没弄懂」的片段，收在两段同一件事，没有无关图引或整日流水账。
第三稿还有一句「我扫了一眼」缺素材依据，**这层轻微的动作添写仍可能发生**。
本轮没有重跑数据库中的既有日记；文风稳定性还要看后续真实生成的新稿。
`sendImageContent=false` 的本机配置仍未覆盖读图主路径。
