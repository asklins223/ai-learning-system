## 2. 产品定位——为什么不是聊天机器人（§5.1）

普通聊天产品的容器是**消息流**；本产品的容器是**知识空间和一次有目标的 Session**。

伴星必须具备通用聊天产品没有的行为：

- 知道用户当前选中的文章、Card、Key Point、星域、确定性血缘和当前 Scene 关系；
- 能在星图中**指向、聚焦、铺路和拉近节点**；
- 能把知识对象放入**共学工作台**，生成可操作场景；
- 能观察用户的结构化动作并**改变下一步**；
- 能回答额外问题，并把回答呈现为**证据卡、对比场景或练习建议**；
- 能明确**结束、安静退场**并把结果还给星图。

## 3. 基础形象描述（年轻星际导航员规格）

**形态约束**：拟人化 + 动画角色——非抽象光球、非工具图标、非写实人类、非只有语音无身体的助手。

**角色设定**：一名来自理解星图的**年轻星际导航员**。

**视觉规格**：

- 约 2.5~3 头身；
- 清晰眉眼嘴手和完整身体语言；
- 发光星纹 + 短披风或围巾式彗尾 + 可变形的导航环；
- 二维动画造型、干净色块、柔和描边和少量空间光效。

**明确避免**：写实 3D 数字人、过度复杂服装、大面积持续粒子。

**角色关系**：并肩探索的**伙伴**，不是监督者、判卷者、电子宠物。

## 4. 统一基础角色与个性化保留规则

- 公测**只交付一个统一基础角色**；
- 外观配色 / 声音 / 轻量动作个性化保留为 **Could**；
- **不得**通过 XP、连续学习、付费抽取或任务完成解锁角色身体、表情和必要动作。

## 7. 动画状态机 CompanionVisualStateV1 与动画语义限制

**状态集**（完整状态表见原方案 §5.2）：

```
dormant
invite_once
navigate
present_evidence
listen
co_manipulate
explain
assessment_handoff
committed_change
uncertain_or_retry
exit_or_hidden
```

**语义限制**：

- 动画只能表达**已经发生的系统状态**，不能伪装评估进度或 canonical 结果；
- `quiet` 未召唤时**不得进入 idle 动画**，只显示**静态中性锚点**；
- `assessment_handoff` 通过**可见退场**表达「伴星导航员不参与判分」；
- `committed_change` **不做烟花 / 连胜 / 夸张庆功**；
- `exit_or_hidden` 在 reduced-motion 下**直接消失**；
- `temporary_hidden` / `global_off` **不留气泡、声音、context 监听、传输、后台调用**。

## 8. 情绪边界

**可以表达**：好奇、专注、共同发现、平静、温和幽默。

**禁止表达**：失望、焦虑、吃醋、孤独、受伤、「等你回来」。

**行为约束**：

- 答错时只关注**知识对象**和**下一种可选操作**；
- **不得**根据摄像头、语音或操作速度推断情绪、暗中切换表情。

## 9. 首版动画资产技术要求与 reduced-motion 规则

**资产技术**：

- 首版动画资产使用**可交互的二维骨骼 / 矢量状态机**（**非** GIF、长视频、LLM 实时生成）；
- W1 原型在 **Rive 或同等引擎**间完成**性能、许可证、离线降级和无障碍评估**；
- `CompanionVisualStateV1`、typed-action 映射和静态 fallback **不绑定供应商私有语义**。

**reduced-motion 规则**：

- reduced-motion 下**取消飞行 / 弹性缩放 / 视差 / 持续漂浮**；
- 角色 / 动画 / 音频加载失败时，通过**静态立绘、图标化手势和标准控件**继续可用。
