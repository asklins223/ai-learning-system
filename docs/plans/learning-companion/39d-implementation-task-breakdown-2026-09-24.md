## 0. 怎么用这份文档

1. **一条顺序，不是三张表。** 39b 的 B0–B7（伴星供给侧）、39c 的四个步骤（制卡链）、39 的 §17 三个阶段，是同一批工作的三种切法。本文把它们合并为 W0–W8 九个波次，每个源批次只出现一次（映射见 §2）。
2. **ID 稳定。** 任务 ID 一经写入不重排、不复用；新增任务追加到所属波次末尾（如 W4-9、W2-8）。波次内顺序即建议执行顺序。
3. **状态五值**：`未动` / `进行` / `部分` / `已落地` / `撤回`。改状态时**同格补证据**（命令、读数或 `file:line`），不写裸的「已完成」。证据只记一处，不另转抄第二张表（一处一个来源，状态列就是唯一台账）。
4. **判据分两层**：确定性判据（能跑命令，先跑）和实机判据（真窗口/真库，后跑）。一次只花一次模型钱：每波末尾真跑一批，见 §3 第 10 条。
5. **冷启动**：新会话接力只看 §1、§3、§4 与所在波次的小节；找不到落点时看 §18。

## 3. 执行纪律（红线）

1. **不用 git 写操作删代码**（尤其 `checkout`/`reset`/批量 revert）；删代码逐块手动删，也别用脚本整文件覆写共享文档（会截掉别人未提交正文）。删除前核对调用方，交付说明里列删除范围。出处：AGENTS.md。
2. **闸纪律**：B0–B6 期间一条守卫都不删；每条删除只在 W6-1，且必须同时拿到 (a) 重放台 `still-leaks=0`、(b) 真实流量 0 触发两份证据。没删掉一条闸之前不许对外说「闸修好了」。出处：39b §9、§11 批次纪律。
3. **事务纪律**：外部模型/转写/图片解析调用一律「短事务准备 → 事务外执行 → 短事务核对保存」；执行接口不接受事务对象，检测到活动事务（含隐式外层）即拒绝。出处：39c §5。
4. **集测分角色**：夹具写用 `DATABASE_URL`/`_MIGRATOR`（超级用户 `ailearn`），被测读写用 `DATABASE_URL_API`（`ailearn_api`，NOBYPASSRLS）/`DATABASE_URL_WORKER`。用超级用户跑被测路径会静默读回全部行，本地绿不算证据。出处：`docker-compose.dev.yml:12-19`、doc 34 L37/L43。
5. **一处一个来源**：任何用户可见读数只准一个来源、一个集合；判据里的数字要能被同一条命令复现，本文的状态列就是唯一台账，不另转抄。
6. **绿的定义**：typecheck 通过 + 0 个失败文件 + 摘要里没有 `Errors` 段（exit=0 藏得住未捕获异常）+ 用例数差额=删除数（不许「莫名少了」）。出处：39b §12。
7. **先确定性后花钱**：每波的确定性用例先全绿，再跑一次真模型批（批量末尾一次，避免反复计费）。出处：39b §11。
8. **UI 只在真窗口算验过**：走 Computer Use 真点，不用脚本冒充；说不清就读不到，默认自己没读到，停手别写进发现清单。
9. **并行会话**：一个 worktree 里可能有别的会话（含在途的 dev 库迁移补账）。动手前 `git status` 看一遍，不抢别人在途文件；改动经 `tsx watch` 当场生效，坏中间态算你的。出处：39b §14。
10. **每轮收尾写进 §19 实施日志**：一行 = 任务 ID + 改了什么 + 命令与读数。上下文紧时先把状态落进本文再继续，不以「下一轮」收尾。
