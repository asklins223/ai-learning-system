# 伴星中心 UI 问题清单与改进方案（2026-09-21）

> 署名：Asklins
>
> 这份文档只谈伴星中心（`.companion-center`，六个页签：记忆 / 对话 / 动态 / 日记 / 人格 / 数据）。
> 所有「现象」都是我在跑起来的桌面端上量出来的，不是读代码推的。文末有复现方法。

## 0. 一句话结论

伴星中心现在同时存在两类毛病：**骨架上它不是一个页面，是六套各自为政的浮层**（切页签会让主面板从 372px 弹到 1044px，星图 chrome 只是被 `visibility:hidden` 藏起来而没有离场）；**皮肤上它有两套冲突的视觉语言**（全局 HUD 的奶油纸 + 伴星自己发明的深玻璃），再叠上 11px 主字号、6 种不对称圆角、8 种按钮配方和几乎为零的转场动效。所以它看起来「烂」不是某一处没做好，是从布局到 token 的每一层都缺一个统一裁决。

**2026-09-21 补充（已定产品决策）**：右上角那颗印章与空间胶囊的合体方式定了——收进同一个灵动岛，折叠时并成一颗、展开时胶囊被岛左缘带着往左滑，动效合同写在 §4（批次 B0，可立刻做）。

## 2. 骨架与层级（最贵的一类问题）

### P1 切页签 = 换页面：主面板宽度瞬间跳 672px

- **实量**：记忆页签下 `.companion-workbench` = `[96,100,372,628]`；其余五个页签 = `[96,100,1044,628]`。宽 372 → 1044，**没有任何过渡**（探针在切换时只抓到 `background-color` 和 `box-shadow` 两条 transition，落在页签按钮自己身上；`transitionProperty` 命中布局属性的元素数 = 0）。
- **根因**：`hud-surface.css:3350-3353` 用 `:not([data-active-tab="memory"])` 把工作台 `right: var(--companion-seat-strip-right); width: auto`。等于「记忆」是一个页签，另外五个是另一种页面。
- **为什么算问题**：用户点的是同一排页签，得到的却是两个不同的产品。左侧列表的位置、宽度、卡片排版全在变，视线锚点每点一次就被重置一次。
- **方案**：
  1. 把「记忆」从六页签里拆出来。伴星中心改成**固定的两段式骨架**：左栏（工作台，恒定 `--companion-bench-w`）+ 右区（详情 / 星图 / 内容）。记忆列表留在左栏，星图作为右区的默认视图；对话 / 动态 / 日记 / 人格 / 数据切换的是**右区内容**，左栏永不动。
  2. 如果坚持六页签平铺，那就反过来：所有页签都用 1044 宽，记忆页签把星图放进右区而不是把左栏压窄。
  3. 两种都行，但**必须选一个**，别留 `:not()` 双轨。
  4. 宽度真需要变时，用 `transition: grid-template-columns 240ms var(--hud-ease-out)`（Chromium 可插值），或者用 `transform` 做视觉位移，别让它瞬移。

### P2 星图 chrome 只是「藏起来」，没离场

- **实量**：对话页签下仍有 **4 个** `.companion-map-*` 元素带矩形且 `visibility: hidden`（含 236×470 的 `.companion-map-index` 右栏，内容高 2118px）。右区那 300px 空带（工作台 right=1140，视口 1440）就是被这批隐形元素占着的。
- **根因**：`hud-surface.css:3355-3362` 用 `visibility: hidden; pointer-events: none` 收起星图 chrome；`companion-center-surface.tsx` 没有按页签卸载它们。
- **为什么算问题**：布局上白占 300px；DOM 上 2118px 的列表常驻；辅助技术树里它们只是被 `visibility` 挡了一下。而且这正是我第一版探针量出 14 条「隐形文字」的原因——连量都会被它骗。
- **方案**：非记忆视图直接不渲染这批节点（条件渲染，或 `display: none`）。注释里写的「从视觉、交互和辅助技术树中一起收起」是对的目标，`visibility` 实现不到它。

### P3 两套表面语言叠在同一屏

- **实量**：同一屏里同时有奶油纸（`.task-title` 标题盘、底部缩放条 `rgb(229,215,185)`）和深玻璃盘（工作台 `rgba(11,33,48,.85)`、星图 HUD、右栏）。按钮配方 **8 种**：61 个用 `rgba(255,255,255,.07)+1.5px rgba(255,252,235,.3)`，11 个用 `.1`，2 个用金色 `rgba(233,198,111,.1)`，43 个是「透明底 + 透明 1.5px 边框 + 16px 字」，另外 3 个各是一种一次性写法。
- **根因**：`HudPage`（`components/hud/HudPage.tsx:23`）给每个 HUD 页发一块 `.task-title` 奶油标题盘，伴星中心又自建了整套深玻璃（`hud-surface.css:2480-2490`）。两套从没合并成一套。
- **方案**：伴星中心**只留一种表面语言**——深玻璃。`.task-title` 在 `page=companion` 时改成深玻璃盘上的一行文字（不用第二个盘），缩放条 / 图例 / 右栏全部改用 `--companion-card-glass` 家族。按钮收敛到 3 个角色：主操作（金色实底）、次操作（玻璃 + 描边）、幽灵（无底无边），用 `.companion-button--primary|secondary|ghost` 三个类，其余配方删掉。

### P4 灵动岛折叠态：空间胶囊被丢在离印章 244px 的地方（→ 见 §4 专章）

- **实量**：`.room-control` 折叠态 = `[991,22,424,48]`，胶囊 `[999,28,126,36]`，印章 `.room-control-trigger` `[1369,27,38,38]`；皮肤 `::before` 折叠时 `opacity:0 / scaleX(0.16)`。也就是说折叠后**药丸皮肤消失、6 个槽位只把 opacity 打成 0（各占 36px 宽一点没缩）**，于是屏幕上留下两个互不相干的浮块，中间 244px 空。展开态里胶囊的位置是 `[999,28,126,36]`——**和折叠态一模一样，它从来没动过**。
- **和星图盘相撞**：胶囊与 `.companion-map-hud` 的重叠面积 = **4549px²，等于胶囊自身 126×36 的 100%**。它不是「寄生」在盘里，是被盘整个压在下面（`z:40` 在盘之上，所以视觉上像盘里的一个控件）。
- **结论**：用户要的不是新建一个灵动岛——`.room-control` 本来就是灵动岛（`HudRoomControl.tsx:37-58` 注释自己写着「上一版灵动岛」）。坏的是**折叠态没收到一起**。方案与动效合同见 §4。

### P5 返回 pill 的焦点环是另一个体系的红

- **实量**：`.return-home` 被聚焦时画的是 `--focus: #9a351d`（`styles.css:22` + `styles.css:68` 的全局 3px 环），而伴星自己的控件用青色 `rgba(131,216,231,.5)`（`hud-surface.css:2753`）。截图里那个红色椭圆就是它。
- **根因**：`hud-surface.css:2743-2752` 的焦点规则枚举了工作台 / 星图 HUD / 索引 / 选择器，**漏了 `.return-home`**。
- **方案**：全站焦点环收成一个 token（`--focus-ring`），伴星作用域内覆盖成青色；`.return-home` 纳入伴星作用域。焦点环颜色不该有两个体系。

### P6 一个 500px 的窗口装 6630px 内容，且没有任何提示

- **实量**：`.companion-tab-panel` 恒为 364×500（记忆页签），`scrollHeight` = **6630px**（61 条记忆），比值 **13.3×**；对话 11.1×。右栏 `.companion-map-index` 464px 装 2118px（4.6×，43 条）。面板底部**直接切在卡片中间**（`mask-image` / 渐隐：无；500px 里完整可见的卡只有 2 张）。
- **根因**：`hud-surface.css:2651-2658` 只有 `overflow-y: auto`，工作台高度由 `--companion-bench-*` 定死。
- **方案**：
  1. 记忆 / 对话列表改成**分页或虚拟列表**（每屏 5-6 条 + 「加载更多」），不做 13 倍滚轮。
  2. 保留内滚时加 24px 底部渐隐 `mask-image: linear-gradient(...)` 和一条「还有 N 条」的计数，让「被切断」变成「还有下文」。
  3. 卡片不许被切一半：滚动容器底部 padding ≥ 卡片高度的一半。

### P7 层级靠 30-40 的魔法数排队

- **实量**：伴星中心内部实际出现的 z 值 = `0, 1, 19, 30, 31, 32, 33`；token 表（`hud-surface.css:2513-2519`）另给了 30/31/32/33/34/35/40 七级。`19` 不在 token 表里。
- **方案**：压到 4 级（内容 / 浮层 / 模态 / 提示），`19` 归位；每次新增浮层要写清它属于哪一级，不许再借相邻数字。

## 3. 可读性：字号、行长、对比度

### P8 正文是 11px

- **实量**：六个页签里出现最多的字号**全部**是 `11px/400`（记忆 222 字、对话 263 字、动态 139 字、日记 46 字、人格 261 字、数据 267 字），12px 只在卡片标题上露面。token 表 `--companion-font-micro: 11px / body: 12px / title: 13px`（`hud-surface.css:2506-2511`），实际执行是 micro 当正文用。
- **为什么算问题**：1440×810 桌面上 11px 中文（约 1.4mm 字高）是「元信息」的尺寸，不是正文。整页读下来眼睛要一直凑近。
- **方案**：正文 `--companion-font-body: 14px`、`title: 15px`、`micro: 12px`（micro 只准用于时间戳 / 计数 / 单位）；行高统一 1.6。改完必须回头收 P6 的滚动比和卡片密度，二者是同一件事。

### P9 一行 63 个汉字

- **实量**：单行文字盒最大宽度——动态 828px、日记 819px、对话 589px。日记正文 13px 时一行约 **63 个汉字**。
- **根因**：`--companion-content-measure: 860px`（`hud-surface.css:2479`）被直接当可读宽度用（`3367-3369`）。860px 对拉丁文尚可，对全角中文远超上限。
- **方案**：中文正文测量宽度 `40-48em`（14px 时约 560-670px），日记正文 `max-width: 42em; margin-inline: auto`；`--companion-content-measure` 降到 660px，多栏表单另用栅格而不是把一栏摊到 860px。

### P10 次要文字这一档全线低于 4.5:1

- **实量**（像素采样，底色取元素四周真实像素）：

  | 位置 | 比值 | 字号 | 前景 | 采样底色 |
  |---|---|---|---|---|
  | 星图搜索行「星图」标签 | **3.37** | 11px/700 | `rgb(139,166,173)` | `(72,76,74)` |
  | 缩放条「17%」 | **4.40** | 11px/400 | `rgb(112,93,77)` | `(229,215,185)` |
  | 缩放条「＋」「−」 | **4.40/4.41** | 16px/400 | 同上 | 同上 |
  | 缩放条「适配」「复位」 | **4.44** | 11px/400 | 同上 | 同上 |
  | 人格预设描述 | **4.25** | 11px/400 | `rgb(169,194,199)` | `(73,82,87)` |
  | 数据「正在读取待处理的冲突」 | **4.32** | 11px/400 | 同上 | `(68,81,95)` |

- **根因**：`--companion-glass-soft: #a9c2c7` 和 `--companion-glass-faint: #8ba6ad`（`hud-surface.css:2482-2483`）在深玻璃上刚好落在 4.2-4.4；奶油盘上的 `rgb(112,93,77)` 是硬编码，没走 token。
- **方案**：把 soft / faint 两档提到 `#c3d6da` / `#a5bcc2`，并加一条**可跑的验收**：探针里所有 `ratio < 4.5` 的文本节点数必须为 0。硬编码色一律换成 token。

### P11 星图标签一律截断到 11 个字，且和节点没有归属关系

- **实量**：记忆页签下 39 个元素被 ellipsis 截断（900 宽时 41），右侧栏每条平均丢 200-500px 文本（「间隔重复是一种学习策略，通…」丢了 496px）。星图标签全部形如「看新概念时更想先看反例…」，画在 `universe-canvas` 上，离它指的那颗星 20-60px，**无引线**；左下角「用户曾误称桌宠为"大肥…」直接被画布边缘切掉。
- **根因**：`companion-center-surface.tsx:127` `UNIVERSE_LABEL_HALF = 95`；`hud-surface.css:3312` 右栏 `white-space: nowrap` + ellipsis。
- **方案**：星图默认只给**固定记忆**画标签（已渲染的 21 条里只有 2 条是「已固定」，其余 19 条是「待确认」，默认全标等于把噪声画满屏），其余悬停 / 选中才出标签，并画 1px 引线 + 2px 命中环；标签盒留 12px 画布内边距，越界改成翻转方向而不是裁掉。右栏每条给两行（正文 + 时间 / 类型），不截断成一行。

## 4. 右上灵动岛：折叠收拢 + 胶囊同步左移（2026-09-21 用户定的产品决策）

> 决策原话：空间胶囊放到右上角红框处，与那颗印章按钮合并成灵动岛；右侧菜单展开时，胶囊同步向左位移；**动画要做好，不要生硬的闪现或平移**。
>
> 下面这版是按现有 `.room-control` 结构写的，不是另起一个组件——重建会把 `HudRoomControl.tsx:96-231` 里那套「先折叠再跳转」「切换回执停车」的逻辑全部丢掉。

### 4.1 现状（为什么它现在不像一个岛）

| 状态 | 药丸皮肤 `::before` | 6 个槽位 | 胶囊位置 | 岛宽 |
|---|---|---|---|---|
| 展开 | `opacity 1 / scaleX(1)` | opacity 1，各 36px | `[999,28,126,36]` | 424px |
| 折叠 | **`opacity 0 / scaleX(0.16)`** | **opacity 0，但仍各占 36px** | `[999,28,126,36]`（没动） | 424px |

- 槽位折叠只打 `opacity`（`hud-surface.css:1917-1924`），**宽度不回收** → 岛永远 424px。
- 皮肤折叠时整个隐藏 → 岛失去外框，只剩胶囊自己的底 + 印章自己的圆。
- 两者合起来：折叠态 = 左边一个胶囊、右边一个圆点、中间 244px 空气。用户圈红框要的就是把这两块并到一起。

### 4.2 结构：不加包裹层，回收槽位自己的宽度

> **本节 2026-09-21 重写。** 初版写的是「把 6 个槽位包进 `div.room-control__slots`」。实测后作废：那 6 个槽位是**完全没有 class 的裸 `<button>`**，只能靠 `> button:not(.room-control-trigger):not(.room-control-space)` 命名；加一层 div 会静默摘掉约 17 条 `> button` 规则（36px 圆底、hover/active/focus、折叠三元组、`.active::after` 圆点）、`nth-child(2..8)` 错峰，以及 `scripts/capture-pages-v3.mjs:155` 的取数。DOM 一行不动。

岛宽在代码里**根本没有声明过**（`hud-pages.css:41` 只给 `right:25px; top:22px`，无 `width`），424px 全由内容撑出来。所以折叠只要让槽位贡献变 0，岛的右缘钉死、左缘自然收进来：

| | 折叠 | 展开 |
|---|---|---|
| 岛宽 | **184px** = 2 边框 + 14 padding + 126 胶囊 + 4 缝 + 38 印章 | **424px**（与今天逐像素相同） |
| 胶囊 | `[1239..1365]` | `[999..1125]` |
| 行程 | 胶囊被布局带着左移 **240px**；印章两态都是 `x=1369`，全程不动 | |

每颗槽位图标的行程互不相同（home 218px、account 18px、印章 0px），因为它们从同一个 4px 缝里被拉开——这正是「槽位从印章里长出来」的读法。包裹层做不到这件事（六个图标会整齐平移同样的 240px）。

四条踩出来的机制，少一条就不成立：

1. **`min-width: 0` 与 `overflow: hidden` 缺一不可。** 槽位是 `display:grid` 的 flex item，自动最小尺寸 = 内容尺寸 = 18px（那颗 svg）。只写 `width:0` 会卡在 18px，岛只收到 **316px**。
2. **`flex: 0 0 auto`，basis 必须是 `auto`。** `hud-surface.css:487-489` 已经写下这条教训：固定 `flex-basis` 会让子元素在药丸里一帧弹出去。
3. **`place-content: center`。** `place-items:center` 只把图标在轨道里居中，而 `w<18` 时轨道仍是 18px 且贴在内容盒起点，图标会左对齐、从右边被切。补上才得到左右对称的光圈式开合。
4. **`gap` 必须清零**（generated 的 `4px` 给 6 个 0 宽 item 照样各留一道 → 28px 死缝，直接违反 §4.5 的间距断言）。改用每项 `margin-inline-start`，且 **margin 也要进 transition**，否则 240px 行程里有 24px 在 t=0 瞬跳。

皮肤与胶囊：

- `::before` 保留 `inset:0`，**删掉 `scaleX(0.16)` 与 `transform-origin: right center`**，两态都 `opacity:1`。岛宽在动，`inset:0` 会跟着长。两条时间轴（皮肤缩放 + 宽度增长）同时跑正是「外框比内容快」的观感来源。
- 胶囊的 `background` / `border-color` / `box-shadow` 一并撤掉（`.room-control` 是 `z-index:40` 的层叠上下文，皮肤的 `z-index:-1` 落在所有子元素之下，不撤就是「药丸里套一颗药丸」双层边框双份阴影）。分隔线用 **`border-inline-end`**，不能用 `::after`——`hud-surface.css:1702` 的 `> button.active::after` 同特异度也打给胶囊（空间菜单打开时它就 `.active`）。`box-sizing:border-box` 让这条缝不占外层宽度，4px 间距不受影响。

### 4.3 动效合同（这是「不要生硬」的全部落点）

> **缓动 2026-09-21 更正。** 初版给位移通道写的是 `cubic-bezier(.22,1,.36,1)`——它首帧斜率 4.55，240px 行程首帧就走 **57px**，直接违反我自己 §4.5 写的「相邻帧 ≤12px」（那个 12 是照 home-v2 的 54px 行程推的，岛行程是它的 4.4 倍）。位移通道改 `cubic-bezier(.4, 0, .2, 1)`，**首帧速度为 0**。

**展开（点印章）**

| 通道 | 时长 | 缓动 | 延迟 |
|---|---|---|---|
| 槽位 `width` / `margin-inline-start` | 320ms（`--hud-island-motion`，已存在） | `cubic-bezier(.4,0,.2,1)` | 0 |
| 槽位 `opacity` | 150ms | `ease-out` | 65ms |
| 槽位 `translateX(8px→0)` | 240ms | `cubic-bezier(.22,1,.36,1)` | 65ms |
| 图标 `hud-slot-icon-in` | **175ms**（原 240） | `(.23,1,.32,1)` | 65→145ms 错峰 |
| 皮肤 `border-color` | 180ms | `ease-out` | 0 |

图标错峰收在 145+175=320ms，与岛宽同一帧结束；今天 145+240=385ms，最后 65ms 是「岛停了图标还在动」——那就是两条时间轴。

**折叠（再点印章 / 点空白 / Esc）**

| 通道 | 时长 | 延迟 |
|---|---|---|
| 槽位 `opacity` | 110ms | 0 |
| 槽位 `translateX` | 160ms | 0 |
| 槽位 `width` / `margin` | 320ms | **80ms** |

总预算 400ms。`(.4,0,.2,1)` 起步速度为 0，所以在 80→110ms 这段重叠里盒子实际闭合不到 0.5px——图标是真的先淡完，门才开始动。

时序必须**折叠写在基础规则、展开写在 `[data-expanded]`**：transition 取的是目标规则，写反了展开会先卡 80ms。另外 `:active`（`:1939`）把 `transition-property` 重写成 4 项白名单，会把 `width`/`margin` 摘掉——按住槽位时被外部折叠（`surface`/`onboardingOpen` effect 或 `SPACE_MENU_OPEN_EVENT`）就是 90ms 瞬移，必须重述。

硬要求：

1. **只用 `width` 表达折叠**，禁止 `display:none` / `visibility` / `max-height`（前两个是瞬移，第三个纵向裁切图标）。
2. **胶囊自己不许有任何 `transition: transform`**，它必须被布局带着走。
3. 皮肤上**禁止加 `backdrop-filter`**：岛宽每帧在变，会每帧重新采样背景（现有实现只把它放在固定尺寸的印章上，是对的）。也不给 `.room-control` 本身加 `overflow`——那会裁掉焦点环和印章的投影。
4. `prefers-reduced-motion`：把 `width`/`margin`/`transform` 整个从 `transition-property` 里摘掉（不是 `duration:1ms` 那种把透明度也一起杀掉的写法），且**这个块必须排在宽度规则之后**，否则同特异度下源码顺序反了，`reduce` 下岛照样动。
5. 键盘：折叠后焦点回到印章；空间菜单开着时 Esc 先关菜单并把焦点给胶囊（现有 `HudRoomControl.tsx:193-197`，别丢）。
6. `COLLAPSE_BEFORE_NAVIGATE_MS`（`HudRoomControl.tsx:58`，现值 320）必须 ≥ 折叠总预算 400 → 取 **420**。否则点「设置中心」会在岛还没关完时就跳转，岛被瞬间掀掉。**这条不是 CSS。**

已知不做（初版列了但实现不了）：折叠期间延后 `pointer-events` 关闭——6 个槽位带 `inert={!isExpanded}`，t=0 就翻，时序无从谈起。`data-motion-mode="off"` 这个钩子在 `.room-control` 上不存在（只有 `.home-v2-hud` 和 `.task-surface` 有），本岛只认 `prefers-reduced-motion`。

### 4.4 与伴星中心页面的重叠：静息态自动归零，展开态算浮层

> **本节 2026-09-21 大幅缩减。** 初版提议加一个 `--hud-top-right-clearance: 472px` 让所有顶部盘避让。核算后作废：

- 折叠岛左缘 = `1440 - 25 - 184 = 1231`，而 `.companion-map-hud` 右缘 1140 → **胶囊一归位，静息态重叠自动变 0**，不需要任何避让。
- 展开时岛（991-1415）仍压住盘 149×48px，但那是**临时浮层**，和它自己的下拉卡 `.home-menu`（`right:25px; top:77px`，同样盖在页面内容上）是同一种语义，关掉就没了。用户 2026-09-21 确认按浮层处理。
- 加避让反而有害：`.companion-map-hud` 变窄会经 `companion-center-surface.tsx:164-176` 的 ResizeObserver 改变 `insets.top`，把 43 个星图标签全部重排一遍——那是 B5 的范围，不该由 B0 触发。

顺带记一个**先前就存在的紧凑态缺陷**（本次一并修，另见 §7 P19）：`@media (max-width:760px)` 把岛高压到 29px、印章压到 23px，但 6 个槽位仍是 36px——generated 样式那条 `23px` 打在 `.room-control span` 上，而 `.hud-surface .room-control span` 特异度更高，媒体查询不加特异度，所以它根本打不到 `button`。结果是岛的内容盒只有 21px，装不下 36px 的槽位、也装不下 36px 高的空间胶囊。
修法分两半：槽位高与图标、印章一起收到 21px；**岛高改成 `auto`**——胶囊是「我在哪个空间、我能不能改」的唯一常驻答案，不能被裁，所以让两行文字决定岛的高度，而不是把它压进 21px。（初版这里写的「岛内容盒 = 29−6−2 = 21px，让所有子元素收进去」是错的：那样必须裁胶囊。）

### 4.5 验收（全部可量，1440×810 与 720×405 各跑一遍）

- 折叠：岛宽 `184`；`trigger.x − (space.right + 4) ≤ 1`；6 个槽位 `rect.width === 0`（这条就是 `min-width:0`+`overflow` 的探测器，删掉会停在 18）；`::before` 的 `opacity === "1"` 且 `transform === "none"`。
- 展开：岛宽 `424`（与今天相同，不得变）、胶囊 `[999,28,126,36]`、印章 `x === 1369` **两态相同**（证明是槽位长出来，不是整条平移）。
- **逐帧连续性**（**初版这条写错了，已替换**）：初版写「相邻两帧差值 ≤12px」，那是照 home-v2 的 54px 行程推的；换算成 px/ms 时我又算错过一次。正确的判据是**行程占比**，与刷新率无关（这台机器实测 9ms/帧 ≈ 110Hz，任何按 60fps 推的绝对阈值都会失效）。页内触发点击，`requestAnimationFrame` 采 `[t, space.x]` 到 520ms，断言：
  - **单帧最大位移 ≤ 行程的 25%**——瞬移的特征就是一帧吃掉 100%，实测平滑曲线峰值 7.5%-14.8%；
  - **`frames ≥ 14`**：帧数下限不可省，只采到 2 帧的样本能骗过任何跳变断言（后台页 rAF 会停，探针必须开 `Emulation.setFocusEmulationEnabled`）；
  - **落定时刻** ∈ 设计时长 ×[0.7, 1.25]（展开 320ms / 折叠 400ms），证明它真在跑动画而不是瞬移后空转；
  - 实测行程 = `6×(槽位+缝)`，且 `x` 展开时单调不增（8px 位移没和宽度抢）。
- 先淡出再关门：逐帧采槽位 `opacity` 与槽位宽度，「淡完时刻」≤「门开始关时刻」，且差值 ≤140ms。
- 重叠：折叠态与 `.companion-map-hud` 重叠 = 0；展开态**断言它等于 149×48**（浮层语义，不许悄悄变大）。
- 静态守卫：胶囊 `transitionProperty` 不含 `transform`；`.room-control` computed 无 `backdrop-filter`；胶囊 `backgroundColor === "rgba(0, 0, 0, 0)"` 且 `borderInlineEndWidth === "1px"`。
- 紧凑态不变式：720×405 下每个 `.room-control > button` 满足 `child.top ≥ island.top && child.bottom ≤ island.bottom`，且岛与 `.companion-compact-mode` 不相交。

## 5. 卡片设计

### P12 记忆卡：三行元信息抢同一层，一屏只放得下 2 张完整的卡

- **实量**：`.companion-record-list` 共 **61 行**，卡高 84-139px、平均 **97px**；在 500px 高的面板里**完整可见的只有 2 张**（其余被上下边缘切断）。一张卡的构成 = 类型（金色 12px/700）+ 状态（灰色 11px，同一基线右对齐）/ 正文一行 / 日期一行。
- **方案**：卡片模板固定四件套——**正文优先**（第一行就是内容，13-14px），元信息（类型 · 状态 · 相对时间）合成一行 12px 灰字放底部；状态用色点 + 文字，不用第二个标签位；操作（固定 / 删除）hover 才出现，常驻位留给正文。同样的高度目标从 2 张完整提到 6-7 张。

### P13 右栏「共同记录」：44px 行高装一行 11px 截断文字

- **实量**：`.companion-map-index button { min-height: 44px }`（`hud-surface.css:3298`）+ `gap: 5px` → 每条 ~49px 里只有 16px 是文字；43 条同一种长相，无分组、无时间、无类型；第二条内容就是「关联内容已不存在」这句错误文案被当成一条正常记录列出来。
- **方案**：44px 最小命中区是给**稀疏操作**的，不是给密集列表的——列表行改成 32px 高 + 键盘走位，靠整行可点而不是靠高度；按日期分组（今天 / 本周 / 更早）；失效项降饱和 + 单独分组，不混在正常项里。

### P14 动态页把内部分析原文当卡片正文

- **实量**：卡片正文直接是「用户多次询问《欧姆定律生成验收》笔记内容，但助手确认该笔记不存在。用户表现出对"必须用工具打开读原文，别凭印象复述"的强烈要求，暗示用户重视信息的真实性和准确性」，另一条「截至当前，用户本周累计学习时长为23分钟，拥有10张活跃卡片和9篇笔记。」
- **为什么算问题**：这是抽取器的中间产物，不是伴星对用户说话。第三人称自指（「用户」）、报数字、把判断过程摊开——三条都撞在已定的伴星文案规矩上（见记忆 `feedback-companion-voice-not-statistics`）。UI 再修，这块文字也还是「系统日志」。
- **方案**：动态卡固定「一句话主张（第一人称）+ 一条可点证据 + 动作」，数字与推理过程收进「看依据」；「待处理」状态用色点表达，不再占一行。

### P15 卡片圆角是歪的，而且歪得很规律

- **实量**：`.companion-center` 内 6 种圆角，主力是 `--companion-radius-chip: 11px 14px 10px 13px`（120 个元素共用），另有 `14/18/13/16`、`19/24/17/21`，和两个椭圆四角 `23px 29px 20px 27px / 27px 21px 29px 22px`、`31px 42px 29px 38px / 35px 30px 43px 31px`。
- **为什么算问题**：手绘感要成立，得让每个元素歪得**不一样**。现在 120 个元素用同一组不对称值，读起来不是「有机」，是「没对齐」。
- **方案**：数据卡 / 列表项 / 控件一律对称圆角（8 / 12 / 16 三档）；手绘不对称只保留在**装饰层**（标题盘、空状态插画），且用 `--companion-radius-organic` 单独一个 token，别让它渗进卡片体系。

### P16 三种描边宽度、两种「看不见」的边框

- **实量**：`1.5px rgba(255,252,235,.3)` ×73、`1.5px rgba(0,0,0,0)` ×43（透明边框照样占布局）、`3px rgba(255,252,235,.62)` ×3、`4px` ×1。
- **方案**：描边收成 1px（分隔）/ 1.5px（卡）/ 2px（强调）三档；透明边框改用 `outline` 或 `box-shadow: inset`，别占布局。

## 6. 动效

### P17 有 hover，没有转场

- **实量**：130ms（43 个元素，`background-color, border-color`）、140ms（15 个元素，四属性）、160ms（页签，`hud-surface.css:2640`）三套时长并存；缓动统一 `cubic-bezier(.23,1,.32,1)`；**整个伴星中心只有 1 个元素带 keyframe 入场动画**（`hud-pop .22s`）。切页签时正文零过渡，主面板宽度零过渡（见 P1）。
- **结论**：不是「动太多」，是**该动的地方全不动**：内容换页、面板变形、卡片进出场，全是硬切。
- **方案**（三条，不加第四条）：
  1. 时长收两档：微反馈 120ms、结构变化 240ms；缓动一个（保留现有那条）。
  2. 页签内容切换：旧内容 `opacity 1→0 / translateY 4px`，120ms；新内容延迟 60ms 后 200ms 进，`translateY -6px→0`。
  3. 列表进出：卡片 160ms + 40ms 步进（最多叠 6 张），删除时先 120ms 收高度再移除。
  4. `prefers-reduced-motion` 现有 72 条规则是够的，新加的一律走同一个 `--motion-scale` 开关。

### P18 状态变化没有反馈

- 点「整理近期对话」「固定」「清除」后没有任何进行中 / 完成的视觉语汇（只有按钮文字变）。方案：统一 `.companion-busy` 微旋转 + 完成后 200ms 底色脉冲；破坏性操作确认态用底色从玻璃转成 `rgba(223,118,87,.16)`（`.companion-danger-action` 已有，复用）。

## 7. 小尺寸下的实际可用性

- **实量**：900×560 时六个页签各 **31×48px**（宽 < 44，`grid-template-columns: repeat(6, minmax(0,96px))` 被压扁，`hud-surface.css:2625`），6 个控件低于最小命中区；720×405 时 `.companion-tab-panel` 只剩 **158px 高，能看到的记忆卡数量 = 0**（页头 + 两个按钮 + 搜索框把整个视口吃完了）。1024×640 面板 330px，约 2 张卡。
- 三个视口都没有横向溢出（`scrollWidth ≤ innerWidth`），所以问题不是溢出，是**固定 chrome 挤压内容区**。
- **方案**：面板高度低于 320px 时，页头说明文字（`companion-panel-heading p`）与「整理近期对话 / 手动添加」折进一个 `⋯` 菜单；页签在 <1100px 改成横向可滑的 chip 条并保证 ≥44×44；紧凑模式（`COMPANION_COMPACT_QUERY`，`companion-center-surface.tsx:132`）默认进「资料」视图而不是把六页签硬塞。

### P19 紧凑态的顶栏岛，装不下它自己的子元素

- **实量**：`@media (max-width:760px)` 把 `.room-control` 压到 `height:29px; padding:3px 4px`（`hud-pages.css:157`）、印章压到 23px（`hud-surface.css:2108`），但 6 个槽位仍是 **36px**——generated 样式里那条 `23px` 打在 `.room-control span` 上，而槽位是 `<button>`，打不到。同一条 `@media` 里的 `.room-control svg{width:11px}` 也是死规则：`hud-surface.css:1680` 的 `> button > svg` 特异度 `(0,2,2)` 压过它的 `(0,2,1)`。
- **为什么算问题**：岛的内容盒只有 21px（29 − 6 padding − 2 边框），36px 的槽位上下各顶出 7.5px；印章 23px 比它要收纳的槽位还小，读起来像「收纳盒比里面的东西大」。
- **方案（已随 B0 实施，见 §4.7）**：分两半。槽位高、图标、印章一起收到 21px（走 `--island-slot-size`）；**岛高改成 `auto`**——胶囊是常驻答案、不能被裁，所以让它的两行文字决定岛高，而不是把胶囊压进 21px。验收 = 「720×405 下每个 `.room-control > button` 满足 `child.top ≥ island.top && child.bottom ≤ island.bottom`，且岛与 `.companion-compact-mode` 不相交」，实测通过（改动前实测胶囊在 `y 7-43`、岛在 `y 10-39`）。

## 9. 我建议不要动的部分

- `prefers-reduced-motion` 已有 72 条规则覆盖，别重做。
- 内容区不要加布局属性动画（`height/width/margin` 逐帧重排 61 张卡 = 掉帧）。**唯一例外是 §4.3 的岛宽**：它只有 8 个子元素、固定 48px 高、且是外框而不是内容，`width` 过渡在这里是正确工具；那种地方不要为了「一律用 transform」的教条改用 FLIP 去重造一遍。
- 缓动 `cubic-bezier(.23,1,.32,1)`（全站）与 `cubic-bezier(.22,1,.36,1)`（岛内 8px 位移、透明度、边框色）都是成熟的，保留。**但大行程的位移通道要另用 `cubic-bezier(.4,0,.2,1)`**：`.22,1,.36,1` 首帧斜率 4.55，在 240px 行程上首帧就走 57px（见 §4.3 的更正）。小位移留快出、大位移要慢起，不是一条曲线通吃。
- token 化本身在做（`--companion-*` 一整套在 `hud-surface.css:2475-2519`），问题在于**有 token 却没执行**（11px 当正文、micro 当 body、圆角三档写成不对称）。先让执行回到 token，再谈新增 token。
