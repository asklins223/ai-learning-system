## Feature Flags

| Flag | 默认值 | 回滚行为 |
| --- | --- | --- |
| `AI_QUESTION_V1_ENABLED` | `false` | 只允许 deterministic question；不由客户端题面产生升级 |
| `RUBRIC_EVALUATION_V1_ENABLED` | `false` | evaluation fail closed；不回退到模型直接决定 outcome |
| `NEXT_PUBLIC_QUESTION_FIRST_UI_ENABLED` | `false` | 回退到只读兼容界面；不得恢复客户端升级权力 |
| `CARD_REPAIR_V1_ENABLED` | `false` | 回退到单次 sanitizeCardOutput |
| `SCHEDULER_POLICY_VERSION` | `discrete-v1` | 保持旧策略 |
| `FSRS_SHADOW_ENABLED` | `false` | 不写 shadow 数据 |

> 关闭 flag 时 fail closed：可回到只读卡片、确定性题目或旧 schedule 展示，但不能恢复客户端题面/outcome 的升级权力。

### 2026-07-25：第五轮审查修复（计划合规性审查）

对照 v0.6 实施计划逐条审查已完成的 M1-M3 代码，发现并修复 5 个问题（详见下文）；

- **[严重] Supersede 查询不兼容 v0.6 key_point schedule**：

  - 修复：全部替换为 `currentSub.*`；

### 2026-07-25：第六轮审查修复（遗留项清零）

修复第五轮记录的 3 项已知未修复项，以及审查中发现的 2 个额外问题，共 5 项：

- **[重要] `question-safety.ts` 无效 evidenceRefId 归类错误（计划 §7.7）**：
  - 无效 evidenceRefId 被归类为 `PROMPT_INJECTION`，混淆了契约违规与注入攻击两种不同性质的拦截原因；
  - 修复：在 `QuestionSafetyReasonCode` 中新增 `INVALID_EVIDENCE_REF: "invalid_evidence_ref"` 独立 reason code；
  - 更新 `question-safety.ts` 中 evidence ref 校验逻辑使用新 reason code；
  - 更新 `question-safety.test.ts` 测试期望值匹配新 reason code；

- **[重要] `generate-validation-question.ts` 事务内未重新计算 source fingerprint（计划 §8.5 step 1）**：
  - 原实现在事务前计算 fingerprint 后直接使用，若事务执行期间 source 被修改（keyPoint claim 变更、evidence 被删除等），写入的 fingerprint 与实际数据不一致；
  - 修复：在 `withJobTransaction` 事务内重新查询 keyPoint、card、evidence 数据并重新计算 `txFingerprint`；
  - 若事务内 fingerprint 与事务前计算值不一致，标记 submission 为 STALE（`fingerprint_changed`），丢弃 AI 输出；
