## 仍阻断 enforce / M1 的事项

1. Worker 的真实 `validation_feedback` writer 尚未写入 `input_refs.userId`；历史 `ai_artifacts` 也需要回填或关系化约束，当前 policy 启用后会正确拒绝这一路径。
2. `jobs` 的 Worker policy 仍允许同 workspace/actor 范围的通用 `SELECT/UPDATE`；actorless 行与缺失/空 user context 的语义必须随 job-specific renew/finish/fail 函数一起收口。
3. 用户私有 RLS 下，多用户 note 删除需要受控级联清理方案；当前 actor transaction 不能证明会删除其他用户的私有派生记录。
4. 还缺真实 HTTP 双 workspace 的搜索、关联写入、批量、导出、删除 0 泄漏矩阵；global identity/control、邀请消费、export/restore 和剩余 DB escape 路径尚未闭环。
5. 1,000 次测试只覆盖 Worker `max: 1` transaction context，不等于完整 API request pool 门禁；双 Worker测试也未覆盖所有真实 handler side effect 与持续续租。
6. 恶意非空 context、actorless finalize、真实 validation handler、代表性 v0.4 forward upgrade/runbook 仍需进入 enforce gate。
7. owner 权限检查与后续 owner 操作仍是两个事务；reindex 现在是长事务且没有并发锁，进入 enforce 前需补一致性/并发决策。
8. 独立 human security/data reviewer 尚未批准 enforce。

因此本轮只能提交为“SEC-01 policy expand / verify preparation，RLS 仍关闭”。
